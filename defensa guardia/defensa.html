1. Resumen Ejecutivo y Justificación

Evolución del Proyecto: Se tomó la estructura HTML inicial y se transformó en un prototipo web funcional y responsivo adaptado a un sistema de guardia médica.

Justificación Técnica: Se implementó un archivo CSS externo centralizado con variables (:root), estructuras combinadas de Flexbox y CSS Grid, reglas media queries para adaptación móvil y 5 estrategias de SEO aplicadas directamente al marcado HTML.

2. Paso 1: Estrategias de SEO en el HTML
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="Sistema web de gestión de guardia médica...">
    <title>Guardia Médica | Sistema de Gestión y Recepción de Pacientes</title>
    <link rel="stylesheet" href="style.css">
</head>
Explicación para la Defensa:
  • lang="es" y charset="UTF-8": SEO/Accesibilidad. Define el idioma e interpretación universal de caracteres (acentos y ñ).
  • meta viewport: SEO/Responsive. Controla la escala de visualización en smartphones.
  • meta description: SEO. Aporta la descripción resumida que indexa y muestra Google en sus resultados.
  • title optimizado: SEO. Incluye términos clave directos del negocio ("Guardia Médica", "Gestión").
3. Paso 2: Variables CSS y Reset Global
:root {
    --color-primario: #0d6efd;
    --color-secundario: #0a3663;
    --color-fondo: #f8f9fa;
    --color-tarjeta: #ffffff;
    --fuente-principal: 'Segoe UI', system-ui, sans-serif;
    --espaciado-md: 1rem;
    --radio-borde: 12px;
}

* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}
Explicación para la Defensa:
  • :root y var(): Centralización de estilos. Permite actualizar colores, espacios o tipografías en un solo lugar y repercutir en toda la app.
  • box-sizing: border-box: Garantiza que bordes y rellenos (padding) no modifiquen el ancho real calculado para las cajas.
4. Paso 3: Maquetación con Flexbox (Encabezado y Menú)
.contenedor-header {
    display: flex;
    flex-direction: column;
    align-items: center;
    gap: var(--espaciado-md);
}

nav.nav-principal ul {
    list-style: none;
    display: flex;
    gap: var(--espaciado-md);
}
Explicación para la Defensa:
  • Flexbox en Header: Organiza la distribución vertical/horizontal del título y la navegación.
  • Flexbox en Menú: Dispone la lista no ordenada (`ul`) en una fila horizontal uniforme mediante `gap`.
5. Paso 4: Maquetación con CSS Grid y Media Queries
.contenedor-principal {
    display: grid;
    grid-template-columns: 1fr;
    gap: var(--espaciado-lg);
}

@media (min-width: 1024px) {
    .contenedor-principal {
        grid-template-columns: 1fr 1.8fr;
    }
}
Explicación para la Defensa:
  • CSS Grid Mobile-First: Define el área principal en 1 sola columna por defecto para pantallas de celular (`1fr`).
  • Media Query (1024px): En pantallas de escritorio se reestructura a 2 columnas asimétricas (`1fr 1.8fr`), separando el formulario de la tabla.
6. Paso 5: Flujo de Git y Control de Versiones
# Creación de rama de desarrollo
git checkout dev
git checkout -b feature/estilos-css

# Guardado y limpieza de commits
git add style.css
git commit -m "refactor: remover comentarios de style.css para entrega limpia"

# Fusión final en dev
git checkout dev
git merge feature/estilos-css
git push origin dev
Explicación para la Defensa:
  • Se utilizó el flujo de trabajo sobre la rama `dev` mediante una rama auxiliar de características (`feature/estilos-css`), manteniendo organizada la rama principal `main` y utilizando prefijos de commits estandarizados (`feat:`, `refactor:`).
